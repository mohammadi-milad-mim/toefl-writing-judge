# TOEFL Writing Assessor

A small command-line tool that sends each candidate response to three independent
LLM evaluators concurrently. Each evaluator uses the relevant ETS-aligned rubric,
returns a Markdown 0–5 assessment, and produces both a minimal-edit 5/5 revision and
an enhanced 5/5 revision.

## Setup

1. Edit `.env` and add your AvalAI API key. The OpenAI-compatible base URL, the three
   requested models, and their current list prices are already configured. Use
   `.env.example` as a clean reference if needed.
2. Install dependencies:

   ```bash
   uv sync
   ```

All three models use AvalAI's OpenAI-compatible Chat Completions endpoint and return
plain Markdown. No provider Structured Outputs feature is required.

## Directory layout

Each task has its own top-level folder. Each question stores its prompt once, and every
assessment run has a separate folder containing the candidate answer and the three
generated model reports:

```text
write_an_email/
└── q001/
    ├── prompt.md
    ├── run_001/
    │   ├── answer.md
    │   ├── claude-sonnet-5.md
    │   ├── gemini-3.5-flash.md
    │   └── gpt-5.6-terra.md
    └── run_002/
        └── answer.md

academic_discussion/
    └── q001/
        ├── prompt.md
        └── run_001/
            └── answer.md
```

The model report files shown above are generated by the script. Before the first run,
a run folder only needs its answer file.

For **Write an Email**, `prompt.md` should contain the complete situation, recipient,
and instructions.

For **Academic Discussion**, keep the complete task in one `prompt.md` file using the
two labels required by the evaluator prompt:

```markdown
Professor’s question:
Should universities require every student to take a financial-literacy course?

Other students’ contributions:
Student 1: ...
Student 2: ...
```

Straight or curly apostrophes are accepted in these two labels. Both sections must be
present and nonempty so they can be inserted into the exact evaluator placeholders.

Accepted question filenames are `prompt`, `question`, or `task` with a `.md` or `.txt`
extension. Accepted answer filenames are `response` or `answer` with either extension.

## Run

Give the script a single question directory:

```bash
uv run python assess.py write_an_email/q001_concert
```

or:

```bash
uv run python assess.py academic_discussion/q001_free_will
```

The task type is inferred from the path. If needed, override it with `--task email` or
`--task discussion`.

All three models run by default. Use aliases or exact model IDs to run only a subset:

```bash
# GPT only
uv run python assess.py write_an_email/q001_concert --models gpt

# GPT and Claude only
uv run python assess.py write_an_email/q001_concert --models gpt claude

# Comma-separated form is also accepted
uv run python assess.py write_an_email/q001_concert --models gpt,claude
```

The script finds every immediate child folder containing an accepted answer filename.
All requests for all runs and all three models are launched concurrently. As soon as
one model finishes, its Markdown file is written directly beside that run's answer and
the completed path is printed while the remaining requests continue. A progress bar
covers the full concurrent batch.

The complete intended Markdown report format is included at the end of each evaluator
prompt. The model response is written directly into its `.md` report; the script then
appends token usage and estimated cost. There is no JSON parsing, Pydantic validation,
`response_format`, or structured-output retry.

Each assessment includes two complete 5/5 rewrites. The first uses the smallest edits
that can credibly fix every score-limiting problem while preserving the original wording
and structure. The second allows broader improvements to development and expression,
but must remain recognizably based on the candidate’s position and useful ideas.

Each individual LLM request has a hard timeout controlled by `LLM_TIMEOUT_SECONDS` in
`.env`. The included value is `240`, or four minutes. A timed-out request writes an
error report without cancelling the other requests.

## Included examples

Four examples are included with one run each:

- `write_an_email/q001_concert/run_001`
- `write_an_email/q002_charity_event/run_001`
- `academic_discussion/q001_free_will/run_001`
- `academic_discussion/q002_urban_growth/run_001`

To assess another response to an existing question, create a sibling folder such as
`run_002` and put only `answer.md` inside it. Running that question directory again
processes every run folder and writes each run's three reports beside its answer.

Each file contains the model's Markdown report. Its final section records input,
cached-input, output, reasoning-output, and total token usage, followed by the configured
rates and an estimated request-cost breakdown. Reasoning tokens are already included in
output tokens, so they are not charged twice.

A failed model call writes its error Markdown file beside the answer, while the other
calls are allowed to finish. The command exits with status `1` if any model request fails.
